# Learnings（skill 自我學習紀錄）

這個檔案由 skill 在使用過程中**自動累積**：每當使用者修正一個決策或表達偏好，
就把它蒸餾成一條可重用的規則記在這裡。skill 每次啟動都會先讀這份檔案。

## 規則格式

```
### <短標題>（YYYY-MM-DD）
- **規則**：一句話，下次直接可執行
- **為什麼**：當時被修正的原因（一句話）
- **適用**：design / timing / audio / workflow
```

寫入原則：
- 記**通用規則**，不記單一影片的細節（具體秒數、專案文案不要進來）
- 與既有規則衝突時**更新舊條目**而不是並列，並改日期
- 已被納入 SKILL.md 正文或 `editing-principles.md` 的慣例**要從這裡刪掉**——
  同一條規則散在三個地方會各自漂移

升級去向（見 SKILL.md 的 Self-learning）：**「不這樣做就會壞」→ `editing-principles.md`；
「這樣做比較好」→ SKILL.md 的設計慣例**。升級後從本檔移除。

### 封面/hook 標題句式（2026-07-27）
- **規則**：hook 標題用「逆境＋具體數字」句式，越短越好；避免工具/過程視角的標題
- **為什麼**：故事反差＋數字的點擊率優於描述製作過程的標題
- **適用**：design

### 剪輯尺度（2026-07-27）
- **規則**：情感鋪陳段（人物故事、快轉 b-roll）不剪；重複性展示畫面（同一畫面反覆捲動）優先剪
- **為什麼**：使用者要求還原被剪的故事段，但接受剪掉重複展示段
- **適用**：timing

### 短片 overlay 密度（2026-07-31）
- **規則**：成品 ≲25s 就不要放章節 chips／頂部 pill；封面＋字幕＋**一個**大字節拍即足夠
- **為什麼**：使用者說「這個片劇情太短了，上面的都不用加」——短片沒有章節可分，頂部 overlay 只是擋畫面
- **適用**：design

### 印章／狀態字要接梗，不要通用詞（2026-07-31）
- **規則**：印章文字要**扣住該片的具體笑點**（把影片裡的專有名詞、身分、數字寫進去），不要用「我服了 / 完成 / 成功」這類萬用詞
- **為什麼**：使用者說通用詞「太樣板了」，要求換口味
- **適用**：design

### 語音起點以響度包絡為準，不能只信 whisper（2026-07-31）
- **規則**：對齊完成後，凡是**停頓後的第一句**都要拿 `ebur128` 逐 0.1s 的 momentary 值覆核起點；
  whisper 的 VAD 常把詞往前拉進停頓裡（實測早 0.35–0.6s），笑點會提前爆雷。
  注意 momentary 是 400ms 尾隨窗、起音會延遲 0.2–0.4s 才反映。
- **為什麼**：本次三句（含兩句笑點）的 whisper 起點都比真實起音早，字幕會比聲音先出現
- **適用**：timing

### 剪點收在起音前 ~0.15s，可順便修正字幕（2026-07-31）
- **規則**：剪空白時，cut 的結束點收在下一句**真實起音前約 0.15s**。
  這樣落在 cut 內的錯誤字幕起點會被 `srcToOut` 夾到接點，等於自動對正。
  笑點前的留白（punchline beat）要**刻意留 0.4–0.5s**，不要當成空白剪掉。
- **為什麼**：喜劇節奏靠停頓，全砍會變得又快又平
- **適用**：timing

### 不要用降噪（2026-08-01）
- **規則**：**任何降噪器都不要用**（`afftdn`／`anlmdn`／`afwtdn`／`arnndn`）。
  站長明確表示不要。技術上也站得住：實測四種降噪器在房間錄音上只換到 0.5–1.4 dB
  的底噪下降，卻會優先削掉最接近底噪的高頻，聲音變悶。
- **為什麼**：站長聽出粗剪「聲音很悶」，並直接指示移除
- **適用**：audio

### 整平人聲之後一定要補頻譜傾斜（2026-08-01）
- **規則**：`dynaudnorm`＋`acompressor` 是**寬頻**增益，等於等比例放大房間而不是放大人聲。
  實測抬一句安靜台詞時：100–300 Hz +22 dB、2k–5k 只有 +15 dB、5k–10k 只有 +11 dB，
  高頻相對掉 7–11 dB ＝「悶」。鏈子裡必須有兩道補償：`equalizer=f=300:t=q:w=1.2:g=-3`
  削箱音、`treble=g=4:f=3200:t=q:w=0.7` 補清晰度。
  ⚠️ `treble`／`bass` 的 `t` 是**寬度單位**：寫 `t=h` 會讓 `w` 變成 0.5 Hz 的極窄共振、
  高頻暴衝 50 dB 並削波。一律 `t=q:w=0.7`。
  **驗收要量頻譜傾斜**：2k–5k 的增益不能比 300–800 少超過 3 dB。
- **為什麼**：只驗逐句 spread 會漏掉這個——spread 合格但聽起來很悶
- **適用**：audio

### 混音先整平人聲，且只信「逐句分離度」（2026-07-31）
- **規則**：配樂蓋掉人聲時，**不要先去動配樂音量**——先量人聲的**逐句 RMS 極差**。
  手機/手持口白實測可達 22 dB，配樂卻恆定，所以「整段 integrated 差 6 dB」是假象，
  安靜的句子照樣被蓋。順序永遠是：**整平人聲（≤8 dB）→ 擺配樂 → 加深 duck → 逐句驗收**。
  驗收指標＝每句人聲 RMS 減掉配樂 RMS **≥ +15 dB**，整段 LUFS 完全不能拿來判斷。
- **為什麼**：使用者反映人聲被蓋掉；一量才發現最糟的一句配樂比人聲還大 8.7 dB，
  而我先前只看整段 integrated 就宣稱「差 5.8 dB、符合設計」
- **適用**：audio

### 台式反諷語氣詞是 ASR 重災區（2026-07-31）
- **規則**：校對時特別檢查**反諷/語氣句型**的同音字，最常見的是
  **「最好是…」被聽成「最後…」**（才怪 → 時間順序，意思完全反掉）；
  同類還有「是喔」/「四喔」、「屁啦」、「哪有」。
  判斷法：看前後句的語氣是否一致——如果左右都是吐槽（屁啦、開玩笑的吧），
  中間那句就不可能是敘事性的「最後」。
- **為什麼**：這句錯字是使用者自己抓到的，我校對時漏掉
- **適用**：workflow

### 正典字幕要在聊天室列出來讓使用者確認（2026-07-31）
- **規則**：校對完的字幕**要在對話裡整份列出來**請使用者過目，不能只塞進 `review.html` 就當作確認過。
  錯字是使用者一眼就抓到、我卻看不出來的東西（他知道自己講了什麼）。
- **為什麼**：把校對稿只放進 review.html，結果錯字撐到第五版才被發現
- **適用**：workflow

### 多段毛片：先合成單一來源，不要改引擎（2026-07-31）
- **規則**：要接多段毛片時，先用 ffmpeg 正規化（統一長寬/fps/音軌，`-fps_mode cfr`、`-t` 鎖每段長度）
  再 concat 成一支 `public/source.mp4`，**所有 cue 用合併後的時間軸**。記下每段位移
  （第二段＝第一段長度、第三段＝前兩段和）寫進 config 註解。
  引擎、`align.py`、`make_review.mjs` 全都假設單一來源時間軸，改成多檔要動三個地方，
  合成只要一次 ffmpeg。轉錄也要**對合成檔重跑**，才會拿到同一時間軸的逐字戳。
- **為什麼**：使用者中途追加第二、三段素材
- **適用**：workflow

### 跨段接點用一個 cut 收掉（2026-07-31）
- **規則**：前一段的尾巴空白＋後一段的開頭空白，寫成**一個橫跨接點的 cut**（例 `[24.55, 25.70]`），
  不要拆成兩個。這樣兩段之間只有一個乾淨接點，不會出現「黑掉一下又跳一下」
- **適用**：timing

### 極短 one-shot 音效不能用 loudnorm（2026-07-31）
- **規則**：長度 < 0.5s 的音效**不要用 `loudnorm=I=...`**——gating 讓 integrated 量測失效
  （會顯示 -70 LUFS 之類的假值），loudnorm 反而把峰值推到 TP 上限，變成整支最刺耳的聲音。
  短音效改**用峰值正規化**：量 `astats` 的 Peak level dB，用 `volume` 調到 -24 dBFS 左右。
  正規化完**一定要回頭量每個檔的 I 與 Peak**，離群的手動修。
- **為什麼**：ui click（0.22s）normalize 後峰值 -4 dBFS，逐字播放時非常刺耳
- **適用**：audio

### 音效優先用「影片本身講的那組素材」（2026-07-31）
- **規則**：如果影片主題就是某組素材（音效包、樂曲、模板），先找使用者本機有沒有那組原檔來當本片音效——
  免費、切題、而且觀眾聽到的正是影片在講的東西。畫面裡的路徑/檔名就是線索，可以直接搜。
- **為什麼**：使用者要「搞笑一點、不要肅殺刺耳」，而影片正在講的那組奇幻音效剛好柔和又切題
- **適用**：audio / design

### 畫面自帶音樂音效的段落要壓 BGM（2026-07-31）
- **規則**：毛片本身有音樂/音效的段落（玩遊戲、播成品、看影片），用 `bgm.ducks`
  把配樂壓 -12 dB 左右，讓畫面的聲音與口白當主角；sidechain 的 2 dB 遠遠不夠。
- **適用**：audio

### 「有在玩」的證據要單獨剪一段（2026-07-31）
- **規則**：遊戲／工具類影片只放場景巡禮與結算畫面，會少掉「這東西實際怎麼玩」。
  在**第一個任務出現之後、第一次結算之前**插入操作快剪，形成
  「接到任務 → 實際動手 → 拿到分數」的完整小迴圈。
- **適用**：design

### 手機直式毛片的 rotation metadata（2026-07-31）
- **規則**：iPhone `.mov` 的 `ffprobe` 會報 1920x1080，但有 rotate 側資料，**實際顯示是 1080x1920**；
  抽格（ffmpeg 會自動套用旋轉）確認長寬再決定 composition 尺寸，不要照 ffprobe 的數字改引擎
- **為什麼**：差點為了「橫式來源」去改 Root.tsx 的合成尺寸，其實不用動
- **適用**：workflow
