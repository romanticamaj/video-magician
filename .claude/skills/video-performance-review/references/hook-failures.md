# Hook 失敗模式

全部是 `[B]`：可爭辯的編輯判斷。每一條都要配上**實際時間點＋抽格畫面**才算數，
不能只憑印象套標籤。

| 失敗模式 | 徵狀 | 怎麼修 |
|---|---|---|
| **有題目沒賭注** | 講了「發生什麼」，沒講「干我何事」 | 把代價／意外／反差提到第一句 |
| **解釋跑在衝突前面** | 流程細節先於錯誤、意外、代價或證據 | 把衝突抽到最前，解釋往後挪 |
| **代名詞先於指涉物** | 「這個／結果／它」出現時觀眾還不知道是什麼 | 換成具體名詞，或先給畫面 |
| **無證據的最高級** | 「太扯／超神」但畫面上看不到東西 | 3–5s 內給可見證據，否則拿掉形容詞 |
| **承諾與兌現不符** | 封面說要測 A，影片證明的是 B | 對齊封面文案與實際兌現 |
| **靜音就看不懂** | 核心張力只存在於聲音 | 補字幕／大字，或改用畫面表達 |
| **封面稅** | 裝飾性封面吃掉 0–0.9s，把人擋在外面 | 縮短封面，或讓封面本身就是鉤子 |
| **鉤子打架** | 標題、口白、大字、音效各講各的前提 | 收斂成一個前提 |
| **句中硬切** | 前面為了縮短機械式砍掉，聽起來不像故意的 | 切在語氣結束處，或補一個節拍 |
| **有懸念沒立場** | 引起好奇，但沒留下觀眾能持有的判斷 | 接上七種對話機制之一 |

## 判定原則

- **「有 hook」和「hook 夠強」分開判。** 有承諾但沒證據＝有 hook、不夠強。
- **0–0.8s 沒有中斷 → 直接是 `repair`**，不管後面多好。
- 修改建議一律要能對應到 config 欄位或明確的 `source_rebuild`／`footage_request`，
  不能停在「開頭要更抓人」這種話。
